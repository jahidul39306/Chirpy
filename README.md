# Chirpy

A Twitter-like backend service built with Go and PostgreSQL. Chirpy is a RESTful API that allows users to create accounts, authenticate, and share short messages called "chirps" (limited to 140 characters).

## Features

- **User Management**: Create users, update profile information, and manage authentication
- **Chirps**: Create, read, and delete short messages with automatic content filtering
- **Authentication**: JWT-based authentication with refresh token support
- **Authorization**: Role-based access control with support for premium (Chirpy Red) users
- **Webhooks**: Polka webhook integration for external events
- **Metrics**: Server health checks and request tracking
- **Content Filtering**: Automatic filtering of profane words in chirps

## Technology Stack

- **Language**: Go 1.25.5
- **Database**: PostgreSQL
- **Authentication**: JWT (golang-jwt/jwt)
- **Password Hashing**: Argon2id
- **UUID Generation**: Google UUID
- **Migration**: Goose
- **Testing**: Testify

## Prerequisites

- Go 1.25 or higher

## Installation

1. Clone the repository:
```bash
git clone https://github.com/jahidul39306/Chirpy.git
cd Chirpy
```

2. Install dependencies:
```bash
go mod download
```

3. Set up environment variables:
```bash
cp .env.example .env
```

Configure the following variables in your `.env` file:
- `DB_URL`: PostgreSQL connection string (e.g., `postgres://user:password@localhost:5432/chirpy`)
- `PLATFORM`: Environment name (dev/prod)
- `SECRET_KEY`: JWT secret key for token signing
- `POLKA_KEY`: API key for Polka webhook integration

4. Run database migrations:
```bash
go run main.go
```

## Running the Server

Start the server on port 8080:
```bash
go run main.go
```

The server will start and listen on `http://localhost:8080`

## API Endpoints

### Health Check
- `GET /api/healthz` - Returns server health status

### User Management
- `POST /api/users` - Create a new user
- `PUT /api/users` - Update user information (requires authentication)
- `POST /api/login` - Authenticate user and receive JWT tokens

### Authentication
- `POST /api/refresh` - Refresh an expired JWT token
- `POST /api/revoke` - Revoke a refresh token

### Chirps
- `POST /api/chirps` - Create a new chirp (requires authentication)
- `GET /api/chirps` - Get all chirps
- `GET /api/chirps/{chirpID}` - Get a specific chirp by ID
- `DELETE /api/chirps/{chirpID}` - Delete a chirp (requires authentication, author only)

### Admin
- `GET /admin/metrics` - Get server metrics (number of requests)
- `POST /admin/reset` - Reset metrics and database

### Webhooks
- `POST /api/polka/webhooks` - Polka webhook endpoint for external integrations

## Database Schema

### Users Table
```sql
CREATE TABLE users (
    id UUID PRIMARY KEY,
    created_at TIMESTAMP,
    updated_at TIMESTAMP,
    email TEXT NOT NULL UNIQUE,
    hashed_password TEXT NOT NULL,
    is_chirpy_red BOOL NOT NULL DEFAULT FALSE
);
```

### Chirps Table
```sql
CREATE TABLE chirps (
    id UUID PRIMARY KEY,
    created_at TIMESTAMP NOT NULL,
    updated_at TIMESTAMP NOT NULL,
    body TEXT NOT NULL,
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE
);
```

### Refresh Tokens Table
```sql
CREATE TABLE refresh_tokens (
    token TEXT PRIMARY KEY,
    created_at TIMESTAMP,
    updated_at TIMESTAMP,
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    expires_at TIMESTAMP,
    revoked_at TIMESTAMP
);
```

## Chirp Validation

- **Maximum length**: 140 characters
- **Content filtering**: Automatic censoring of prohibited words: "kerfuffle", "sharbert", "fornax"
- Filtered words are replaced with `****`

```json

}
```

Common HTTP status codes:
- `200 OK` - Successful request
- `201 Created` - Resource successfully created
- `400 Bad Request` - Invalid request parameters
- `401 Unauthorized` - Missing or invalid authentication
- `500 Internal Server Error` - Server error
